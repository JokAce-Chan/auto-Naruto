# 替身计时器 · 使用说明

> 目标：雷电模拟器对局中，当顶部能量条数值“恰好减 1”时，自动启动/重置 14.50 秒倒计时，
> 以半透明置顶框显示左右两侧独立倒计时。
>
> 本版本已按源项目「六道带土计时器2.0」重写识别与规则层：仅保留 **AI 模式（ONNX 空豆模型 best.onnx）**，
> 传统（灰度采样）模式已移除；AI 模式内提供 **值判定 / 空豆判定** 两种判定方式可切换。

## 1. 安装与启动

- 方式一（推荐）：运行 `tools/publish.ps1` 后，进入 `publish` 文件夹，双击 `NaruttoTimer.App.exe`（默认框架依赖，需本机已装 .NET 8；如已联网可改用 `-SelfContained` 生成免装版本）。
- 方式二（开发）：在仓库根目录执行 `dotnet run --project src\NaruttoTimer.App`。

首次启动后，程序会在可执行文件同目录下创建 `data/`（配置与事件日志）。

## 2. 首次连接

1. 启动雷电模拟器，进入任意对局（页面顶部需显示能量条）。
2. 点击 `[刷新设备]`，在下拉框中选择目标设备（白底黑字）。
   - 下拉列表只显示序列号，例如 `emulator-7834`；雷电模拟器一般形如 `emulator-xxxx`。
3. 点击 `[连接]`，建立 screenrecord 视频流（首次自动查找 scrcpy/adb 与 FFmpeg 组件）。
4. 点击 `[开始识别]`，进入识别循环，预览区实时显示画面。

> 识别运行中切换设备会提示“正在识别中，请先停止识别”——先点 `[开始识别]`（已变为停止态）手动停止，再切换设备。
> 找不到 FFmpeg：请在 `[设置]` 中把 `scrcpy/FFmpeg 目录` 指向 `scrcpy-win64-v4.1\scrcpy-win64-v4.1`。

## 3. 区域标注（重要）

识别依赖两个归一化区域：**左侧能量条**、**右侧能量条**。

- 连接并预览后，可直接在**主界面预览区拖拽**两个框体（只有在有帧时才可用）：
  - 框内拖动 = 整体平移；拖动边缘/四角 = 缩放。
  - 左右能量条强制**同高、同宽、顶边对齐**，拖动任一侧会联动另一侧。
- 需要精确微调时点 `[区域标注]` 打开弹窗，用数字输入框直接填写坐标，或 `[从画面回读]`、`[恢复默认]`。
- 修改后点 `[测试识别]` 验证，确认能输出左右值后再 `[保存]`。

> 区域采用**归一化坐标（0~1，相对整帧）**，与视频分辨率无关；窗口尺寸变化不会错位。
> 视频帧为整帧（1280×720），不再裁切顶部条带。

## 4. 识别模式

仅保留 AI 模式：使用 `assets/best.onnx`（YOLOv8，单类=空豆，输入 128×128）推理；
左右能量条垂直拼接后一次推理，空豆框中心落在上半部分即计左侧、下半部分计右侧。

工具栏 `[判定方式]` 下拉框可选两种判定方式（默认值判定）：

- **值判定**：值 = `6 − 空豆数`（clamp 到 0~6），看“值恰好减 1”触发（与源项目行为一致）。
- **空豆判定**：直接看空豆数，看“空豆恰好加 1”触发；不受值上限夹断影响。

> 两种方式数学上等价（值减 1 ⟺ 空豆加 1）；区别在于空豆超过值上限时，值判定会因 clamp 停在 0 而不再触发，空豆判定仍能判定。
> 切换判定方式会重置稳定基线与倒计时，避免切换瞬间误触发。

相关参数在 `[设置]` 中可调：置信度（0.7）、NMS（0.25）、推理间隔（125ms）、稳定帧数（3）。

> `assets/best.onnx` 缺失或加载失败时，状态栏会提示，且 `[开始识别]` 会被拒绝（不再回退传统模式）。
> 推理间隔调大可降低 CPU 占用，调小则更灵敏（默认 125ms≈8FPS）。

## 5. 触发规则

- 连续 **3 帧**读到同一数值才算“稳定值”（避免单帧闪断误判）。
- 触发条件取决于判定方式：值判定看稳定值**恰好比上一次少 1**，空豆判定看稳定空豆数**恰好比上一次多 1**；左右两侧独立计算。
- 触发后该侧倒计时从 **14.50s** 重新起算，再次减 1 则重置（不叠加）；归零后保持显示 `0.00`。
- 每帧识别读数都参与判定。

## 6. 置顶框设置

- 位置锁定：控制面板开关；锁定时不可拖动/缩放。
- **背景透明度**与**数字透明度**是两个独立滑块，互不影响（数字单独控制透明度）。
- 数字颜色：左绿右红（默认），可在 `[设置]` 中改 `#RRGGBB`。
- 显示格式 `0.00  0.00`（无方括号、无标签），字号随框高、间距随框宽。

## 7. 数据保存

- `[数据保存]` 打开事件列表；`[导出 CSV]` / `[导出 JSON]` 保存到指定位置。
- 事件按日期写入 `data/yyyy-MM-dd/events.jsonl`（字段：时间/侧别/旧值/新值/动作）。
- 识别、触发、连接状态等日志写入 `data/yyyy-MM-dd/log.txt`。
- 预览区右上角 `[导出帧]` 可把当前帧存为 PNG，便于排查标注与识别效果。

## 8. 常见问题

- 预览关闭后识别照常运行：`实时预览` 开关只隐藏画面，不影响识别。
- 识别结果一直为 `0/0`：确认区域标注覆盖到能量条，且画面处于对局顶部条带。
- 提示“AI 模型不可用”：确认 `assets/best.onnx` 存在且可读（发布目录中随程序一同分发）。
- 模拟器断开：状态变黄“重连中”，程序自动重连并重新推送视频流。
- 识别运行中退出：会弹窗确认。

## 9. 项目结构（发布）

```
publish/
├─ NaruttoTimer.App.exe     # 主程序
├─ assets/                  # best.onnx（AI 模式识别必需）
└─ vendor\scrcpy\           # adb.exe、scrcpy.exe、scrcpy-server、FFmpeg DLL
```
